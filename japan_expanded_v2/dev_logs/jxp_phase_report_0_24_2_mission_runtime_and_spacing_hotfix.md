# 日轮诸道 0.24.2：任务刷新与排布修复

## 目标

本次修复同时处理两类运行态问题：路线或国体变化后任务未刷新、旧任务消失或叠加，以及任务列声明顺序错乱造成的异常空白和长连线。

## 运行证据与根因

- 2026-07-10 的 `error.log` 仍记录 `DOM_japanse_missions_*` 与 JXP 任务组的 `mission.cpp:353` 重叠。
- 旧存档把原版任务组和带 BOM 前缀的 JXP 任务组序列化在 `country_missions` 中。
- 0.24.1 将原版任务组改名为 `jxp_disabled_vanilla_*`。这使存档里的原键无法在当前任务注册表中解析，因而无法被 `swap_non_generic_missions` 正常清退。
- 34 个 JXP 任务组中有 4 个源码顺序不递增：国家、宫廷、东亚、太平洋。原版 1.37.5 的 23 个日本任务组全部按 `position` 递增声明。
- 截图中的“一统更新 -> 武家诸役 -> 火器诸局”正好服从错误的源码声明顺序，而不是数值行顺序，证明仅校验唯一坐标不足以保证渲染正确。

## 已实现

1. 原版日本任务覆盖文件保留全部 23 个原始任务组键名，并在 `potential_on_load` 与 `potential` 中永久设为 `always = no`。旧存档现在有同名失活墓碑可供刷新清退。
2. 任务刷新改为两阶段：路线操作后立即交换一次，次日隐藏事件再交换一次。
3. 新增任务指纹自愈事件。它在读档启动时立即检查，并以低频 MTTH 继续兜底；通过 `has_mission` 检查 23 个旧原版锚点、5 类大名家系和 9 种统一后路线组合。发现缺失、跨路线残留或旧原版任务时，清除卡住的 pending 标记并复用两阶段刷新。
4. 新增 0.24.2 一次性迁移 `jxp_migration_v023.7`，用于旧存档清理 pending 状态、规范路线并刷新任务。
5. 物理重排国家、宫廷、东亚、太平洋四个任务组。所有 34 个自定义任务组现均严格按递增 `position` 声明。
6. 宫廷列由尾部 `28/30/32` 压缩为与国家列一致的 `1,3,...,27`。统一后两条公共列均为 14 个节点，不再存在截图中的尾部长空白。
7. 生成器排除 6 个故意带 BOM 的兼容别名，避免机械重排破坏其字节锁定格式。
8. 验证器新增源码顺序与空行宽度约束：倒序、同序、连续任务间距大于 2，或任一有效国家配置出现超过 1 行的全树纵向空洞，均直接失败。

## 验证结果

- 通用 EU4 校验：通过。
- Clausewitz：`177/177` gameplay scripts 通过。
- 任务：`238` 个 ID、`34` 个任务组、`188` 个 tag/路线/宗教/DLC 组合通过。
- 任务刷新：2 个规范交换点、41 个 helper 调用、6/6 BOM 别名、运行态指纹精确匹配。
- 有效拓扑：188 个组合均为完整 5 列，无通用任务回填、同槽竞争、坐标碰撞或失效前置。
- 单元测试：`36/36` 通过。
- 三个生成器重复运行后：`IDEMPOTENCE_CHANGED=0`。
- `eu4-modding` skill：`Skill is valid!`。
- 未启动 EU4；当前结论为 static-safe，不声称 runtime-confirmed。

## 许可后的游戏内回归路线

1. 完全退出并重启 EU4，避免任务文件热加载残留。
2. 读取发生问题的存档，推进至少 2 天，让 0.24.2 迁移和次日复核完成。
3. 检查统一后国家、宫廷两列是否在同一高度结束，且“一统更新”“武家诸役”“火器诸局”等任务按历史顺序出现。
4. 切换一次路线或国体，确认当前打开的任务面板立即更新；次日再次打开时内容保持一致。
5. 保存并重新读档，确认已完成任务仍保留，且原版日本任务和其他路线任务没有重新混入。
6. 检查新生成的 `error.log`，不得新增 `mission.cpp:353` 日本任务组重叠。

## 后续开发约束

- 不得重命名为旧存档提供兼容的任务组墓碑键。
- 每个任务组必须按源码中的 `position` 严格递增；连续声明最多空一行。
- 所有路线、宗教、tag 和任务结构变化必须调用同一个两阶段刷新 helper。
- 新路线必须加入运行态任务指纹和 188 状态有效拓扑矩阵后才能发布。
